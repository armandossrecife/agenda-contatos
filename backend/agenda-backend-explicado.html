Como funciona o backend da Agenda de Contatos

Uma API REST que guarda contatos (nome, vários telefones, vários e-mails e um endereço) num banco MySQL. Foi escrita em Java 7 puro, sem frameworks: Servlets recebem as requisições, um serviço valida os dados e um DAO conversa com o banco via JDBC.

  • Java 7 (bytecode 1.7)
  • Tomcat 7 com Servlet 3.0
  • MySQL 5.7 via JDBC
  • Gson 2.8.9 para JSON
  • 10 classes, 868 linhas
  • 4 testes JUnit 4
  • Empacotado como WAR em Docker
Web: recebe HTTP e responde JSON Serviço: normaliza, valida e delega Persistência: SQL e transações Modelo: objetos que circulam entre as camadas Banco MySQL

Clique em qualquer classe do diagrama para ver sua descrição. Cada camada só conhece a camada imediatamente abaixo; o modelo é compartilhado por todas.

A ideia em três frases

Cada URL /api/contatos… cai no ContatoServlet, que herda da ApiServlet o tratamento comum (codificação, JSON, erros e o “disfarce” de PUT e DELETE para o Flash). O servlet converte o JSON em um objeto Contato e entrega ao ContatoService, que limpa e valida os dados antes de chamar o ContatoDao. O DAO executa SQL parametrizado em transação e devolve o contato pronto, que volta ao cliente como JSON.

Camada web

br.ufpi.agenda.web

ApiServlet

abstrata, 139 linhas

Classe base de todos os endpoints. Sobrescreve service() para aplicar regras comuns antes de despachar para o método certo.

  • Define UTF-8 na requisição e na resposta e desliga cache (Cache-Control, Pragma).
  • Em um POST, procura X-HTTP-Method-Override ou ?_method= e despacha para doPut ou doDelete. Usa switch com String, recurso novo do Java 7.
  • parametroDaQueryString() lê parâmetros só da query string, para não consumir o corpo JSON.
  • json() e erro() padronizam as respostas. Com ?suppress_response_codes=true o status HTTP vira sempre 200.

ContatoServlet

@WebServlet("/api/contatos", "/api/contatos/*"), 158 linhas

Implementa o CRUD HTTP. Extrai o id da URL, converte o corpo com Gson e traduz exceções em códigos HTTP.

  • idDaUrl() lê o pathInfo; id não numérico gera 400 “Id inválido”.
  • ValidacaoException vira 400 com a lista detalhes; SQLException vira 500 e é registrada no log.
  • Na criação, devolve 201 e o header Location com a URL do novo contato.

HealthServlet

@WebServlet("/api/health"), 36 linhas

Verificação de saúde. Informa versão do Java e do servidor, tenta abrir uma conexão e reporta o produto e a versão do banco. Responde UP com 200 ou DOWN com 503. Útil como health check de contêiner ou balanceador.

Camada de serviço

br.ufpi.agenda.service

ContatoService

48 linhas

Fachada das regras de negócio. Valida antes de gravar, força id = null na criação e usa o id da URL na atualização (o id do corpo é ignorado). Recebe DAO e validador pelo construtor, o que permite trocar por dublês em testes.

ContatoValidator

101 linhas, sem dependência de banco

Primeiro normaliza, depois valida, acumulando todos os erros em vez de parar no primeiro.

  • Normalização: trim, texto vazio vira null, itens vazios e duplicados saem das listas.
  • Nome obrigatório, até 120 caracteres. E-mail até 150 e no formato algo@algo.algo.
  • Telefone: de 6 a 30 caracteres entre dígitos, espaço e + ( ) - .
  • Limites do endereço: rua 200, CEP 20, cidade 100, estado 60, país 60.

ValidacaoException

checked exception, 32 linhas

Carrega a lista de erros e monta a mensagem juntando-os com “; ”. A junção é manual porque String.join só chegou no Java 8.

Camada de persistência

br.ufpi.agenda.dao

ContatoDao

238 linhas

JDBC puro com PreparedStatement (protege contra SQL injection) e try-with-resources (fecha conexões automaticamente).

  • inserir e atualizar rodam em transação manual: setAutoCommit(false), commit ou rollback.
  • Na atualização, telefones e e-mails antigos são apagados e reinseridos na ordem recebida.
  • Telefones e e-mails são gravados em lote (addBatch) com a coluna ordem.
  • Na leitura, carrega as listas de todos os contatos com duas consultas IN (…), evitando o problema N+1.
  • A exclusão apaga só a linha de contato; as listas saem por ON DELETE CASCADE.

ConnectionFactory

final, 37 linhas

Carrega o driver com.mysql.jdbc.Driver e abre conexões via DriverManager. Lê DB_URL, DB_USER e DB_PASSWORD do ambiente; sem elas, usa jdbc:mysql://db:3306/agenda com usuário e senha agenda.

Modelo

br.ufpi.agenda.model

Contato e Endereco

POJOs Serializable, 38 e 41 linhas

Objetos simples com getters e setters, serializados diretamente pelo Gson. Os setters de Contato trocam null por lista vazia ou new Endereco(), então o resto do código nunca precisa checar nulo nessas propriedades. O endereço não tem tabela própria: vive nas colunas de contato.

  1. Entrada comum. O Tomcat entrega a requisição a ApiServlet.service(), que configura UTF-8 e cache e decide qual método chamar. Para um POST sem override, chama doPost().
  2. Conversão. ContatoServlet lê o corpo inteiro, rejeita corpo vazio e converte o JSON em Contato. JSON malformado gera 400.
  3. Regras. ContatoService.criar() chama o validador, que limpa os dados e lança ValidacaoException se houver qualquer erro.
  4. Gravação. ContatoDao.inserir() abre uma conexão, desliga o autocommit, insere o contato, recupera o id gerado e grava as listas. Qualquer falha desfaz tudo.
  5. Resposta. O servlet devolve 201 com o contato completo em JSON e o header Location: /api/contatos/{id}.

Como a listagem evita o problema N+1

Uma implementação ingênua faria uma consulta de telefones e outra de e-mails para cada contato: com 100 contatos, 201 consultas. O DAO faz sempre três, qualquer que seja o tamanho da lista.

Do JSON às tabelas

Um único objeto JSON é dividido em três tabelas. A coluna ordem guarda a posição de cada item, para que as listas voltem na mesma sequência.

Só envia GET e POSTPOST com ?_method=PUT ou DELETE (ou o header X-HTTP-Method-Override) é despachado para doPut ou doDelete.
Não entrega ao ActionScript o corpo de respostas 4xx e 5xxCom ?suppress_response_codes=true o status HTTP é sempre 200 e o código real vai no campo status do JSON.
Bloqueia chamadas a outro domínio ou portacrossdomain.xml na raiz autoriza SWFs de qualquer origem a chamar a API.

Pontos de atenção

  
O código é limpo e didático, mas alguns aspectos precisam de cuidado antes de um uso real.

  

    
Alta
Arquivos ausentes no pacote
Faltam o script SQL de criação das tabelas e o docker-compose.yml citado na ConnectionFactory. Sem eles o projeto compila, mas não sobe completo.

    
Alta
Sem autenticação
Qualquer cliente que alcance a porta pode listar, alterar e apagar contatos.

    
Média
crossdomain.xml aberto para qualquer domínio
allow-access-from domain="*" deixa SWFs de qualquer site chamarem a API. O próprio comentário pede restrição em produção.

    
Média
Detalhes internos nas respostas 500
A mensagem da SQLException vai para o cliente, o que pode expor nomes de tabelas ou do host do banco.

    
Média
Sem pool de conexões
Cada operação abre uma conexão nova com DriverManager. Sob carga, isso é lento e pode esgotar conexões do MySQL. Um DataSource do Tomcat resolveria.

    
Baixa
Busca com LIKE '%texto%' e listagem sem paginação
O curinga inicial impede o uso de índice, e GET /api/contatos devolve todos os registros. Ok para uma agenda pequena, não para milhares de contatos.

    
Baixa
Pilha tecnológica fora de suporte
Java 7, Tomcat 7 e MySQL 5.7 já não recebem atualizações de segurança. A escolha faz sentido para compatibilidade com um ambiente legado, mas deve ser consciente.
